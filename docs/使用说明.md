# rftool 使用手册 — ESP32-C5 Wi-Fi 无线电攻击工具

> **仅用于已授权的安全测试、自有网络、CTF 竞赛与安全研究。**
> 对未授权网络发起 deauth / beacon flood 等攻击属违法行为。

---

## 1. 这是什么

rftool 是基于 Waveshare **ESP32-C5-WIFI6-KIT** 开发板的 Wi-Fi 无线电工具，固件烧录到板子后，通过串口终端或 Wi-Fi 就能操控。覆盖 **嗅探 / 注入 / 追踪导出 / HTTP 远程控制 / TUI 交互** 五大类功能。

**能干什么：**
- **嗅探**：单信道监听 + 1-13 信道自动轮询，抓包导出 pcap 给 Wireshark 分析
- **Deauth 注入**：双向 Deauth 帧，把设备踢下线（测防御 / CTF 抓握手）
- **Beacon Flood**：伪造大量假 AP 名称，测试 WIDS / 客户端行为
- **Probe Flood**：广播探测请求，测试 AP 响应能力
- **追踪与导出**：自动追踪周围 AP/Client/握手包，支持 dump 表格打印和 xport csv|json 离线分析
- **HTTP REST API 远程控制**：板子本身开 SoftAP，手机/电脑连上即可 Web 控制（无需串口）
- **TUI 高级交互**：彩色表格、抓包直方图、命令历史、一键打开控制页、本地导出

**硬件环境：**
| 项 | 值 |
|---|---|
| 开发板 | Waveshare ESP32-C5-WIFI6-KIT |
| 芯片 / 模组 | ESP32-C5-WROOM-1（RISC-V 240MHz，双频 Wi-Fi 6，16MB Flash + 8MB PSRAM） |
| 连接 | USB 线接 H2 口（CH343P 桥接 UART0 → COM4），115200 8N1 |
| LED | 板载 WS2812 RGB（GPIO27），状态可视化 |
| 软件 | ESP-IDF v5.5.3 · Python 3.14 · pyserial |

**RGB 灯状态：**
| 颜色 | 状态 | 含义 |
|---|---|---|
| 紫色（常亮） | BOOT | 启动中，Wi-Fi 初始化 |
| 蓝色（常亮） | IDLE | 空闲待命，可以输命令 |
| 绿色（常亮+闪） | SNIFF | 嗅探中，每帧闪一下 |
| 红色（快闪） | INJECT | 注入 deauth/beacon/probe |
| 亮红（快闪） | ERROR | 出错 |

## 3. 两种操控方式

### 方式一：TUI 交互终端（强烈推荐）

`powershell
D:\Python\python.exe scripts\tui.py COM4
`

**支持的功能：**
- 命令历史（↑↓ 翻历史，Ctrl+R 搜索）
- 彩色输出（BEACON 灰青 / DEAUTH 红字 / DATA 灰 / ERROR 亮红）
- dump 输出自动转为对齐表格（列宽适配、厂商上色）
- 实时 pcap 录包（-o 参数）
- 状态变化提示（--- SNIFF ch=6 pkts=0 ---）
- Ctrl+C 退出时打印统计

**TUI 本地命令（不发给板子，本地处理）：**
`
/display db       → 美化展示当前追踪表 (AP/Client/EAPOL)
/display hist     → 抓包长度直方图
/http open        → 用默认浏览器打开 http://192.168.71.1 （需先 http start）
/export <file>    → 将串口收到的 export 结果保存到本地文件
/help             → TUI 本地命令帮助
Ctrl+C            → 退出并打印统计
`

录包用法：
`powershell
# 不录包，纯交互
D:\Python\python.exe scripts\tui.py COM4

# 一边操作一边录 pcap
D:\Python\python.exe scripts\tui.py COM4 -o capture.pcap
`

### 方式二：裸串口终端

用任意串口工具（PuTTY / minicom / Windows Terminal）连 COM4，115200 8N1。
缺点：无命令历史、无彩色、无 pcap 录包、无表格美化、无本地命令。但够用。

### 4.2 status — 查看当前状态

`
rftool> status
META,WIFI,STATUS,state,SNIFF,channel,6,auto_ch,1,sniff_total,142,inject_total,0,aps,13,clients,8,eapols,2
`

输出是机器可解析的 META 行，字段含义：
| 字段 | 含义 |
|------|------|
| state | IDLE / SNIFF / INJECT |
| channel | 当前信道（IDLE=0） |
| uto_ch | 是否处于自动轮询模式（0/1） |
| sniff_total | 累计抓帧数 |
| inject_total | 累计注入帧数 |
| ps | AP 追踪表条目数 |
| clients | Client 追踪表条目数 |
| apols | EAPOL 握手条目数 |

### 4.3 sniff — Wi-Fi 嗅探

**用途**：监听指定信道上所有 802.11 帧，输出可读摘要 + raw hex。

**单信道模式：**
`
rftool> sniff 6              # 信道 6 永续嗅探
rftool> sniff 6 --count 50   # 抓 50 帧后自动停
rftool> sniff 11 -n 100      # -n 是 --count 短写
rftool> stop                 # 手动停
`

**自动信道轮询模式（sniff auto）：**
`
rftool> sniff auto                    # 默认 1000ms 切一个信道（1→2→…→13→1 循环）
rftool> sniff auto --dwell 200        # 200ms 切一个信道（覆盖率高）
rftool> sniff auto -d 3000            # 3s 驻留，适合信道少的环境
rftool> stop
`

每帧输出两行：
`
PKT,WIFI,MGMT,BEACON,236,-45,aa:bb:cc:dd:ee:ff,ff:ff:ff:ff:ff:ff,MyHomeAP
HEX,d4 00 00 00 ff ff ff ff ff ff aa bb cc dd ee ff aa bb cc dd ee ff 80 bf ...
`
- PKT 行：TYPE,SUBTYPE,长度,RSSI,源MAC,目MAC,BSSID,SSID
- HEX 行：raw 802.11 帧（无 FCS），供主机重组 pcap

配合 TUI 录包：
`powershell
D:\Python\python.exe scripts\tui.py COM4 -o capture.pcap
# 在 TUI 里输入 sniff auto -d 300
# Ctrl+C 退出，Wireshark 直接打开 capture.pcap
`

### 4.4 dump — 打印追踪表

**用途**：把 sniff 期间收集的 AP/Client/EAPOL 哈希表打印出来。

`
rftool> dump all        # 同时打印 aps / clients / eapols 三张表
rftool> dump aps        # 仅 AP（含 SSID / 信道 / RSSI / 加密 / PMF / 厂商 / 计数）
rftool> dump clients    # 仅 Client
rftool> dump eapols     # 仅 EAPOL 握手记录
`

输出是 CSV 格式行，TUI 会自动对齐成漂亮的表格：
`
AP    BSSID              SSID                 CH  RSSI  ENC    PMF  Vendor  BCN# DATA#
AP    28:15:a4:02:46:f9  TopSpeed-8046        6   -61   WPA2   1    HiWiFi  12    3
AP    a0:10:77:12:11:82  congfeng             6   -90   WPA2   0    Phicomm  6    0
AP    c4:5e:5c:48:fb:64  <hidden>             6   -92   WPA2   0    Unknown  3    0
`

### 4.5 xport — 导出追踪表

**用途**：把追踪表导出成可离线分析的 CSV / JSON 文件。

`
rftool> export csv     # CSV（每行 = 一条记录，先 AP 后 Client 后 EAPOL）
rftool> export json    # JSON（{"aps": [...], "clients": [...], "eapols": [...]}）
`

配合 TUI /export 本地命令，可把导出结果一键存到电脑：
`
（在 TUI 中）
rftool> export json
→ TUI 自动识别 EXPORT 行，输入 /export myscan.json 即保存。
`

### 4.6 stop — 停止当前操作

停止正在进行的嗅探、自动轮询或注入。
`
rftool> stop
`

### 4.7 deauth — Deauth 帧注入

**用途**：发送 802.11 deauth 帧，强制断开目标设备与 AP 的连接。双向同时发（AP→STA + STA→AP）提高命中率。

`
rftool> deauth -b aa:bb:cc:dd:ee:ff -s 11:22:33:44:55:66 --count 10   # 踢特定设备
rftool> deauth -b aa:bb:cc:dd:ee:ff --count 20                          # 广播踢全 AP 设备
rftool> deauth -b aa:bb:cc:dd:ee:ff                                      # 持续踢（直到 stop）
rftool> deauth -b aabbccddeeff -s 112233445566 -n 50 -r 1 -i 100        # 自定义
rftool> stop
`

| 参数 | 说明 | 默认值 |
|---|---|---|
| -b | 目标 AP MAC（必填） | — |
| -s | 目标设备 MAC；省略=广播 | 广播 |
| --count / -n | 发多少帧；0=持续 | 0 |
| --reason / -r | 802.11 reason code | 7 |
| --interval / -i | 每帧间隔 ms | 0（最快，配合 taskYIELD ≈ 50fps） |

### 4.8 eaconflood — 伪造 Beacon 洪水

**用途**：大量发送伪造 beacon 帧，每帧随机 BSSID + SSID（带前缀），制造"假 AP 海"。

`
rftool> beaconflood -p TESTAP --count 100
rftool> beaconflood -p FAKE_ -i 50       # 持续（直到 stop），50ms 间隔
rftool> stop
`

| 参数 | 说明 | 默认值 |
|---|---|---|
| -p | SSID 前缀（必填），每帧追加 6 位随机数字 | — |
| --count / -n | 发多少帧；0=持续 | 0 |
| --interval / -i | 每帧间隔 ms | 0 |

### 4.9 probeflood — Probe Request 洪水

**用途**：广播大量 probe request（随机源 MAC），测试 AP 的响应。

`
rftool> probeflood --count 200
rftool> probeflood -i 10
rftool> stop
`

| 参数 | 说明 | 默认值 |
|---|---|---|
| --count / -n | 发多少帧；0=持续 | 0 |
| --interval / -i | 每帧间隔 ms | 0 |

### 4.10 http — HTTP REST API 远程控制

**用途**：板子开 SoftAP（默认 SSID 
ftool-AP，无密码，网段 192.168.71.0/24），同时启动 HTTP 服务器，手机/电脑连上就能 Web 控制，无需串口。

`
rftool> http start                              # 用默认参数启动
rftool> http start --ssid MyRFTool --pass 12345678   # 自定义 SoftAP（密码 min 8 位）
rftool> http status                             # 查看运行状态
rftool> http stop                               # 关闭 HTTP + 释放 SoftAP
`

连上 AP 后浏览器访问 http://192.168.71.1，会看到交互式 Web 面板。也可以直接调用 REST API。端点清单：

| 方法 | 路径 | 说明 | 请求体（示例） |

## 5. 输出格式速查

固件输出三种行，都是机器可解析的逗号分隔格式：

`
META,WIFI,<key>,<value>,...        # Wi-Fi 子系统状态/事件/错误
META,HTTP,<key>,<value>,...        # HTTP 子系统状态
PKT,WIFI,<type>,<subtype>,<len>,<rssi>,<src>,<dst>,<bssid>,<ssid>
HEX,<hex bytes space-separated>    # raw 802.11 帧（无 FCS）
AP,<bssid>,<ssid>,ch<N>,rssi<N>,...  # dump / export 行
CLIENT,<mac>,<bssid>,rssi<N>,...
EAPOL,<src>,<dst>,<type>,<step>,...
`

**META 行常见模式：**
`
META,WIFI,STATUS,state,IDLE,channel,0,auto_ch,0,sniff_total,0,inject_total,0,aps,0,clients,0,eapols,0
META,WIFI,SNIFF,START,channel,6,count,50
META,WIFI,SNIFF,AUTO,START,dwell_ms,200
META,WIFI,SNIFF,DONE,total,50
META,WIFI,INJECT,START,type,DEAUTH,target,...
META,WIFI,INJECT,DONE,sent,50
META,WIFI,ERR,msg,nothing_running
META,HTTP,STATUS,running,1,ssid,rftool-AP,ip,192.168.71.1,sta,1
META,HTTP,START,ok,1
META,HTTP,STOP,ok,1
META,WIFI,EXPORT,csv,done,aps,13,clients,8,eapols,2
META,WIFI,EXPORT,json,done,aps,13,clients,8,eapols,2
`

## 6. 实战场景

### 场景一：CTF 无线题 — 抓 4-way 握手

`
步骤：
1. 自动轮询找目标 AP
   rftool> sniff auto -d 500
   （等 10s）
   rftool> stop
   rftool> dump aps    # 看目标 AP 的 BSSID + 信道
   → 假设找到目标 ch=6, bssid=28:15:a4:02:46:f9

2. 开始持续嗅探 + 录 pcap
   # 在 TUI 里：
   D:\Python\python.exe scripts\tui.py COM4 -o handshake.pcap
   rftool> sniff 6

3. 另开终端，发 deauth 踢掉已连接的设备
   rftool> deauth -b 28:15:a4:02:46:f9 --count 5

4. 设备重连 → 4-way handshake → dump eapols 看是否抓到
   rftool> dump eapols
   → 看 step=1,2,3,4 是否都有

5. 停止嗅探 + 用 aircrack-ng 破解
   rftool> stop
   aircrack-ng handshake.pcap -w wordlist.txt
`

### 场景二：测试 WIDS — Beacon Flood

`
1. 启动你的 IDS 监控
2. rftool> beaconflood -p WIDS_TEST -n 500
3. 检查 IDS 是否告警"假 AP 洪水"
4. rftool> stop
`

### 场景三：测试 802.11w (PMF) 防护

`
1. dump aps 看目标 AP 的 pmf 字段是否为 1
2. 发 deauth
   rftool> deauth -b <AP MAC> -s <客户端 MAC> --count 10
3. 如果客户端没断 → PMF 生效
   如果客户端断了 → PMF 未正确配置
`

### 场景四：无线环境普查

`
rftool> sniff auto -d 200
（等 30 秒，每个信道 200ms × 13 ≈ 2.6s，可轮转 10 轮）
rftool> stop

rftool> dump aps        # 打印所有发现的 AP
rftool> dump clients    # 打印所有发现的客户端
rftool> export csv      # 导出成 CSV 放到 Excel 分析
`

### 场景五：HTTP 远程控制（手机也能操控）

`
1. 启动 HTTP 服务
   rftool> http start --ssid MyRFTool --pass 12345678

2. 手机连上 Wi-Fi "MyRFTool"，密码 12345678

3. 手机浏览器访问 http://192.168.71.1
   → 打开 Web UI 面板：
     • 一键单信道嗅探 / 自动轮询
     • deauth / beaconflood / probeflood
     • 查看 AP / Client 表
     • 下载 CSV / JSON 导出

4. （可选）TUI 中 /http open 也能打开面板
`

### 场景六：教学演示 — 802.11 帧结构

`
1. TUI 录包
   D:\Python\python.exe scripts\tui.py COM4 -o lesson.pcap
   rftool> sniff 6 -n 100

2. 用 Wireshark 打开 lesson.pcap
   • Beacon 帧：Frame Control + Duration + DA + SA + BSSID + SSID IE
   • Data 帧：加密 payload
   • Probe Request：SSID wildcard（空 SSID）
   • 过滤：wlan.fc.type == 0 (mgmt) / 1 (ctrl) / 2 (data)
`

### 场景七：离线分析 — 导出 JSON → Python

`
1. 先扫一遍
   rftool> sniff auto -d 200
   (30 秒后)
   rftool> stop
   rftool> export json → 复制 JSON 到 scan.json

2. Python 分析
   import json
   with open('scan.json', encoding='utf-8') as f:
       d = json.load(f)
   # 信号最强 top5 AP
   for ap in sorted(d['aps'], key=lambda x: x['rssi'], reverse=True)[:5]:
       print(f"{ap['ssid']:30s} ch{ap['channel']:2d} RSSI={ap['rssi']:3d} {ap['vendor']}")
   # 有多少开启了 PMF？
   print("PMF-capable APs:", sum(1 for a in d['aps'] if a['pmf']))
`

## 7. 常见问题

### Q: 中文 / 特殊 SSID 显示乱码？
PowerShell 默认编码不是 UTF-8。解决：
`powershell
chcp 65001          # 切到 UTF-8 编码
# 再运行 TUI
`
推荐直接用 TUI（	ui.py），内部用 UTF-8 解码，不受终端影响。

### Q: COM4 被占用 / 拒绝访问？
别的程序（上一个 TUI / PuTTY / monitor.py）还开着。关掉重试。

### Q: 烧录后板子一直重启（bootloop）？
bootloader / partition 地址烧错。正确地址看 uild/flash_args：
`powershell
cd C:\Users\CN112\Desktop\esp32c5\rftool\build
 = "D:\Espressif\python_env\idf5.5_py3.14_env\Scripts\python.exe"
 = "D:\Espressif\frameworks\esp-idf-v5.5.3\components\esptool_py\esptool\esptool.py"
&   --chip esp32c5 --port COM4 --baud 921600 --before default_reset --after hard_reset --no-stub write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x2000 bootloader\bootloader.bin 0x10000 rftool.bin 0x8000 partition_table\partition-table.bin
`

### Q: sniff 没抓到包？
- 信道对不对？中国 2.4G 常用 1/6/11；试试 sniff auto -d 200 轮询
- RSSI 太低（<-90）抓不到也正常
- 换个靠近路由器的位置

### Q: deauth 没踢掉设备？
- 目标 AP 可能开启了 PMF (802.11w)，deauth 会被丢弃（dump aps 看 pmf 字段）
- MAC 写错了，先用 sniff 确认
- 2.4G / 5G 信道选错：rftool 目前仅跑 2.4G（信道 1-14）

### Q: RGB 灯不亮？
- 检查 GPIO27 接线 / RGB_CTRL 门控
- status 命令看固件是否正常启动
- 重新烧录，看串口是否有 "RGB: WS2812 init ok, GPIO=27"

### Q: http start 失败？
- 密码太短（必须 ≥ 8 字符）
- 上次没 http stop 就再调用会报 ESP_ERR_INVALID_STATE（reboot 或 stop 后重试）
