# rftool 使用手册 — ESP32-C5 Wi-Fi 无线电工具

> **仅用于已授权的安全测试、自有网络、CTF 竞赛与安全研究。**
> 对未授权网络发起 deauth / beacon flood 等攻击属违法行为。

---

## 1. 这是什么

rftool 是基于 Waveshare ESP32-C5-WIFI6-KIT 开发板的 Wi-Fi 无线电工具，固件烧进板子后，通过串口终端就能操控。

**能干什么：**
- **嗅探**：监听周围所有 Wi-Fi 流量，抓包导出 pcap 给 Wireshark 分析
- **Deauth 注入**：发送断连帧，把设备从 Wi-Fi 踢下去（测防御 / CTF 抓握手）
- **Beacon Flood**：伪造大量假 AP 名称，测试 IDS / 客户端行为
- **Probe Flood**：广播探测请求，探测周围 AP 响应能力

**硬件要求：**
| 项 | 值 |
|---|---|
| 开发板 | Waveshare ESP32-C5-WIFI6-KIT |
| 芯片 | ESP32-C5（RISC-V 240MHz，双频 Wi-Fi 6，8MB PSRAM） |
| 连接 | USB 线接 H2 口（CH343P 桥接 UART0），115200 baud |
| LED | 板载 WS2812 RGB（GPIO27），状态可视化 |

**RGB 灯状态含义：**
| 颜色 | 状态 | 含义 |
|---|---|---|
| 紫色（常亮） | BOOT | 启动中，Wi-Fi 初始化 |
| 蓝色（常亮） | IDLE | 空闲待命，可以输命令 |
| 绿色（常亮+闪） | SNIFF | 正在嗅探，每收到一帧闪一下 |
| 红色（快闪） | INJECT | 正在注入 deauth/beacon/probe |
| 亮红（快闪） | ERROR | 出错了 |

## 2. 安装与烧录

### 前置条件
- ESP-IDF v5.5.3 已安装在 `D:\Espressif`
- Python 3.14 在 `D:\Python\python.exe`
- pyserial 已装（`pip install pyserial`）

### 三步搞定

```powershell
cd C:\Users\CN112\Desktop\esp32c5\rftool

# 1. 编译固件
.\scripts\build.ps1

# 2. 烧录到板子（自动找 COM 口）
.\scripts\flash.ps1

# 3. 连接板子
D:\Python\python.exe .\scripts\tui.py COM4
```

看到 `rftool>` 提示符就说明就绪了。

> **COM 口怎么看**：设备管理器 → 端口 → 找 CH343 的那个（通常是 COM4 或 COM5）

## 3. 两种操控方式

### 方式一：TUI 交互终端（推荐）

```powershell
D:\Python\python.exe scripts\tui.py COM4
```

功能：
- 命令历史（↑↓ 翻历史）
- Tab 补全命令名
- 彩色输出（BEACON 灰青 / DEAUTH 红字 / DATA 灰）
- 实时 pcap 录包（`-o` 参数）
- 状态变化提示（`--- SNIFF ch=6 pkts=0 ---`）
- Ctrl+C 退出时打印统计

```powershell
# 不录包，纯交互
D:\Python\python.exe scripts\tui.py COM4

# 一边操作一边录 pcap
D:\Python\python.exe scripts\tui.py COM4 -o capture.pcap
```

### 方式二：裸串口终端

用任意串口工具（PuTTY / minicom / Windows Terminal）连 COM4，115200 8N1。

缺点：没有命令历史、没有彩色、没有 pcap 录包。但够用。

## 4. 命令手册

键入 `help` 查看中英双语命令列表。每条命令支持 `--help` 查看详细参数。

### 4.1 `help` — 查看命令列表

```
rftool> help
命令列表 / Commands:
  help         显示帮助 | Show this help
  status       显示状态和计数器 | Show state and counters
  sniff        启动 Wi-Fi 混杂模式嗅探 | Start promisc sniff
                  用法: sniff <1-14> [--count=<n>]
  stop         停止当前嗅探/注入 | Stop sniff/inject
  deauth       构造 deauth 帧注入 (仅限授权使用) | Deauth inject
                  用法: deauth -b <bssid> [-s <station>] [opts]
  beaconflood  伪造 beacon 洪水 (仅限授权使用) | Beacon flood
                  用法: beaconflood -p <prefix> [opts]
  probeflood   probe request 洪水 | Probe req flood
                  用法: probeflood [opts]
```

### 4.2 `status` — 查看当前状态

```
rftool> status
META,WIFI,STATUS,state,SNIFF,channel,6,sniff_total,142,inject_total,0
```

输出是机器可解析的 `META` 行，字段含义：
- `state`：IDLE / SNIFF / INJECT
- `channel`：当前信道
- `sniff_total`：已抓帧数
- `inject_total`：已注入帧数

### 4.3 `sniff` — Wi-Fi 嗅探

**用途**：监听指定信道上所有 802.11 帧，输出可读摘要 + raw hex。

```
rftool> sniff 6              # 信道 6 永续嗅探
rftool> sniff 6 --count 50   # 抓 50 帧后自动停
rftool> sniff 11 -n 100      # -n 是 --count 的短写
rftool> stop                 # 手动停
```

每帧输出两行：
```
PKT,WIFI,MGMT,BEACON,236,-45,aa:bb:cc:dd:ee:ff,ff:ff:ff:ff:ff:ff,MyHomeAP
HEX,d400 0000 aabb...
```
- `PKT` 行：类型/子类型/长度/RSSI/源MAC/目MAC/BSSID/SSID
- `HEX` 行：raw 802.11 帧（无 FCS），供主机重组 pcap

**配合 TUI 录包**：
```powershell
D:\Python\python.exe scripts\tui.py COM4 -o capture.pcap
# 在 TUI 里输入 sniff 6
# 抓完后 Ctrl+C，用 Wireshark 打开 capture.pcap
```

### 4.4 `stop` — 停止当前操作

停止正在进行的嗅探或注入。

```
rftool> stop
```

### 4.5 `deauth` — Deauth 帧注入

**用途**：发送 802.11 deauth 帧，强制断开目标设备与 AP 的连接。

```
# 踢特定设备
rftool> deauth -b aa:bb:cc:dd:ee:ff -s 11:22:33:44:55:66 --count 10

# 广播 deauth（踢该 AP 下所有设备）
rftool> deauth -b aa:bb:cc:dd:ee:ff --count 20

# 持续发送（直到 stop）
rftool> deauth -b aa:bb:cc:dd:ee:ff
rftool> stop

# 自定义 reason code 和间隔
rftool> deauth -b aabbccddeeff -s 112233445566 --count 50 --reason 1 --interval 100
```

参数说明：
| 参数 | 说明 | 默认值 |
|---|---|---|
| `-b` | 目标 AP MAC（必填） | — |
| `-s` | 目标设备 MAC；省略 = 广播 | 广播 |
| `--count` / `-n` | 发多少帧；0 = 持续 | 0 |
| `--reason` / `-r` | 802.11 reason code | 7 |
| `--interval` / `-i` | 每发间隔 ms | 0（最快） |

> 固件同时发 AP→STA 和 STA→AP 双向 deauth，提高命中率。

### 4.6 `beaconflood` — 伪造 Beacon 洪水

**用途**：大量发送伪造 beacon 帧，每帧随机 MAC + SSID，制造"假 AP 洪水"。

```
rftool> beaconflood -p TESTAP --count 100 --interval 50
rftool> beaconflood -p FAKE_       # 持续，直到 stop
rftool> stop
```

| 参数 | 说明 | 默认值 |
|---|---|---|
| `-p` | SSID 前缀（必填），每帧追加随机数字 | — |
| `--count` / `-n` | 发多少帧；0 = 持续 | 0 |
| `--interval` / `-i` | 每发间隔 ms | 100 |

### 4.7 `probeflood` — Probe Request 洪水

**用途**：广播大量 probe request（随机源 MAC），探测周围 AP 响应。

```
rftool> probeflood --count 200 --interval 50
rftool> stop
```

| 参数 | 说明 | 默认值 |
|---|---|---|
| `--count` / `-n` | 发多少帧；0 = 持续 | 0 |
| `--interval` / `-i` | 每发间隔 ms | 100 |

## 5. 实战场景

### 场景一：CTF 无线题 — 抓 4-way 握手

**目标**：抓到 WPA2 四次握手包，用于离线字典破解。

```
步骤：
1. 先嗅探找到目标 AP 的 BSSID 和信道
   rftool> sniff 6 -n 50
   # 看 PKT 行里的 BEACON，找到目标 AP 的 MAC

2. 开始持续嗅探 + 录 pcap
   # 在 TUI 里：
   D:\Python\python.exe scripts\tui.py COM4 -o handshake.pcap
   rftool> sniff 6

3. 另开一个终端，发 deauth 踢掉已连接的设备
   rftool> deauth -b <目标AP MAC> --count 5

4. 设备重连时会发 4-way handshake
   # TUI 会显示 EAPOL 帧

5. 停止嗅探，用 aircrack-ng 破解
   rftool> stop
   # 然后：aircrack-ng handshake.pcap -w wordlist.txt
```

### 场景二：测试 IDS / 客户端异常检测

**目标**：验证你的无线入侵检测系统（WIDS）能不能发现 beacon flood。

```
1. 启动你的 IDS 监控
2. 发 beacon flood
   rftool> beaconflood -p INTRUSION_TEST --count 500 --interval 20
3. 检查 IDS 是否告警
4. rftool> stop
```

### 场景三：测试 802.11w (PMF) 防护

**目标**：验证开启了 PMF（Protected Management Frames）的客户端能否抵抗 deauth。

```
1. 确认目标 AP 和客户端都开了 PMF
2. 发 deauth
   rftool> deauth -b <AP MAC> -s <客户端 MAC> --count 10
3. 如果客户端没断 → PMF 生效（deauth 被丢弃）
   如果客户端断了 → PMF 未正确配置
```

### 场景四：无线环境侦察

**目标**：了解周围有哪些 AP、信号强度、有没有隐藏 SSID。

```
rftool> sniff 6 -n 200
# 看 PKT 行：
#   BEACON 帧 = AP 在广播，SSID 字段 = AP 名称
#   "<hidden>" = 隐藏 SSID 的 AP
#   RSSI = 信号强度（-40 很强，-80 很弱）
#   PROBE_REQ = 有设备在找哪些 SSID
```

### 场景五：教学演示 — 802.11 帧结构

```
1. 录包
   D:\Python\python.exe scripts\tui.py COM4 -o lesson.pcap
   rftool> sniff 6 -n 100

2. 用 Wireshark 打开 lesson.pcap
   - 看 Beacon 帧结构：Frame Control + Duration + DA + SA + BSSID + SSID IE
   - 看 Data 帧的加密 payload
   - 看 Probe Request 的 SSID wildcard
   - 过滤：wlan.fc.type == 0 (mgmt) / 1 (ctrl) / 2 (data)
```

## 6. 输出格式速查

固件输出三种行，都是机器可解析的：

```
META,WIFI,<key>,<value>,...     # 状态/事件/错误
PKT,WIFI,<type>,<subtype>,<len>,<rssi>,<src>,<dst>,<bssid>,<ssid>
HEX,<hex bytes space-separated>  # raw 802.11 帧
```

**META 行常见模式：**
```
META,WIFI,STATUS,state,IDLE,channel,0,sniff_total,0,inject_total,0
META,WIFI,SNIFF,START,channel,6,count,50
META,WIFI,SNIFF,DONE,total,50
META,WIFI,INJECT,START,type,DEAUTH,target,...
META,WIFI,INJECT,DONE,sent,50
META,WIFI,ERR,msg,nothing_running
```

## 7. 常见问题

### Q: 中文 help 显示乱码？
PowerShell 默认编码不是 UTF-8。解决：
```powershell
chcp 65001          # 切到 UTF-8 编码
# 然后再运行 TUI
```
或者用 TUI 工具（`tui.py`），它内部用 UTF-8 解码，不受终端编码影响。

### Q: COM4 被占用 / 拒绝访问？
别的程序（上一个 TUI / PuTTY / monitor.py）还开着。关掉重试。

### Q: 烧录后板子一直重启（bootloop）？
bootloader 地址烧错了。正确地址看 `build/flash_args`：
```powershell
cd C:\Users\CN112\Desktop\esp32c5\rftool\build
$py = "D:\Espressif\python_env\idf5.5_py3.14_env\Scripts\python.exe"
$esptool = "D:\Espressif\frameworks\esp-idf-v5.5.3\components\esptool_py\esptool\esptool.py"
& $py $esptool --chip esp32c5 --port COM4 --baud 921600 --before default_reset --after hard_reset --no-stub write_flash --flash_mode dio --flash_freq 80m --flash_size 2MB 0x2000 bootloader\bootloader.bin 0x10000 rftool.bin 0x8000 partition_table\partition-table.bin
```

### Q: sniff 没抓到包？
- 确认信道对不对（中国 2.4G 常用 1/6/11）
- 确认附近确实有 Wi-Fi 信号
- RSSI 太低（<-90）的 AP 抓不到也正常

### Q: deauth 没踢掉设备？
- 目标 AP 可能开了 PMF (802.11w)，deauth 会被丢弃
- MAC 地址写错了，用 `sniff` 先确认
- 2.4G 和 5G 不一样，确认目标 AP 在 2.4G

### Q: RGB 灯不亮？
- 检查 GPIO27 接线
- 用 `status` 命令看固件是否正常运行
- 烧录是否成功（看串口有没有启动日志）
